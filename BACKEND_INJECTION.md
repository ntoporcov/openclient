# Backend Injection: Current Boundary

September 9, 2026: public automatic detection is the user-approved default and only public policy, with no API picker. This supersedes Legacy-default and explicit Experimental/v2 opt-in instructions. Experimental "mostly works" is still the confidence goal, not a released SDK, full parity, all-harness independence or a built second target. The remote rollout flag remains Track Later, separately from the approved default change. Final source verification retains its exclusion and combined-run failure. The fresh automatic-detection build is now installed on Nic iPhone; launch failed because the phone was locked. Dated handoffs describe only their own passes.

## Public Connection Policy

- New connections and public saved-server loading use `automatic`; saved `legacy`, `v2` and missing preferences migrate to `automatic`. The public loader is used by both the main app and headless Shortcuts. Explicit internal/test overrides remain supported and captured by the factory, rather than overwritten by public migration.
- Authenticated `GET /api/health` selects v2 only for valid `healthy: true`, string `version`, integer `pid >= 0`. Unavailable 404/405, successful HTML or recognized minimal legacy `{"healthy":true}` permits `/global/health` fallback. Authentication 401/403, timeout/network/TLS, other HTTP errors and other malformed/unhealthy responses fail; no silent fallback. Internal Legacy skips the probe; internal explicit v2 never falls back.
- The resolved API remains fixed for the `BackendConnection` lifetime. Neither bootstrap/operation failure nor SSE reconnect renegotiates it; mutations are never automatically retried across routes or profiles.
- Public preference migration does not retype historical widget, Live Activity, window or cache records: existing profile IDs stay unchanged, absent historical profiles remain legacy, and no migrated-record type/schema is added. Raw `serverID` and Keychain identity remain unchanged.
- Plaintext-to-Keychain migration requires verified readback. Existing Keychain credentials, including blank values, win. Deferred failure preserves original persisted raw bytes and blocks centralized metadata/save/edit/delete/remember writes so no path discards the only credential copy. The new secure-storage error offers user retry. Main-app and headless public loading share this safety boundary; factory overrides do not bypass credential preservation.
- The experimental-v2 banner appears only after successful bootstrap for the actual bound backend UUID, not merely a requested profile. Loading/overlays and inactive connection state hide it. Dismissal is per connection lifetime, not a new persistent acknowledgement; SSE reconnect does not reset it. Global Forms have priority; the banner is nonblocking and never gates chat.
- Report a Bug and Help use the same shared Support URL (`AppSupportURLs.swift`), the bare `https://github.com/ntoporcov/openclient/issues` without query/prefill. Notice and secure-storage error source keys/translations are included. Main confirmed current lint passed for 1,492 entries across seven catalogs; the cold-position fix adds no copy. This documentation pass did not rerun lint.
- Experimental read-through/offline behavior under automatic detection is unvalidated. Before a successful network probe the API profile is unknown; no-network startup cannot read the v1 cache as a substitute. This intentional known-profile boundary permits neither legacy fallback nor historical record relabeling. Prior live-discovery/503-transcript cache evidence does not validate cold offline bootstrap.

## What Is Real Today

Core backend injection works through the existing stores and facades. Another harness can supply project discovery, session lifecycle/search, chat history/submission/interruption, model/agent catalogs, and normalized live mutations without constructing an `OpenCodeAPIClient`.

| Contract in `OpenCodeIOSClient/Backends/BackendConnection.swift` | Responsibility |
| --- | --- |
| `BackendFactory` | `connect() async throws -> BackendConnection`; capture configuration and create a fresh connection lifetime per call. |
| `BackendProjectsService` | Project snapshot and optional current project/default directory. |
| `BackendSessionsService` | Scoped list/cursor pages, lookup, create, rename, delete, and search. |
| `BackendChatService` | Transcript/cursor pages, submit, and interrupt. |
| `BackendModelsService` | Scoped agent/provider/model catalog and defaults. |
| `BackendEventSource` | Main-actor `start(receive:)` and `stop()`; one upstream event owner. |

Concrete optional services on `BackendConnection` are declared in `BackendCommandsService.swift`, `BackendWorktreeServices.swift`, `BackendSessionFormsService.swift`, and, in pass 5, `BackendSessionSelectionService.swift`:

| Optional property / protocol | Responsibility and limit |
| --- | --- |
| `commands` / `BackendCommandsService` | Catalog, typed command admission and canonical action-turn/attention evidence. Acceptance/idle is not successful completion. |
| `projectLifecycle` / `BackendProjectLifecycleService` | Directory search and explicit project resolution/discovery; not metadata writes or arbitrary repository initialization. |
| `worktrees` / `BackendWorktreesService` | Inventory, create, remove and inventory refresh; explicit destination-parent requirement and force-required result. Refresh never means reset. |
| `worktreeReset` / `BackendWorktreeResetService` | Separate destructive reset contract; the production factory supplies it only for legacy. |
| `sessionForms` / `BackendSessionFormsService` | Pending/read/state, typed reply and cancellation through the shared native form engine. Unknown outcomes reconcile reads, not mutation retries. |
| `globalForms` / `BackendGlobalFormsService` | Pass 6 computed optional conformance of `sessionForms`, not a separate constructor slot. Adds `pendingGlobalForms(scope:) -> BackendGlobalFormInventory` with response-canonical directory/workspace location; inherited references retain origin for read/state/reply/cancel. |
| `sessionSelection` / `BackendSessionSelectionService` | Session-scoped `setModel`/`setAgent` writes that must precede prompt submission. Absent this service, selections travel in `BackendSubmission`; a capability name alone is insufficient. Production v2 supplies `OpenCodeV2SessionSelectionService`, legacy does not. |

`BackendPendingInputReading` is a separate optional read-evidence protocol, not another `BackendConnection` property. The v2 selection service also conforms to it; its pending read is explicitly restricted to exact next-17155. A missing pending ID is unknown, never permission to repost.

`BackendConnection` holds these services, a descriptor, capabilities, health, and a unique lifetime ID. Its `eventStream()` fans out to subscribers; removing the last subscriber stops the source. `close()` finishes subscribers and rejects stale callbacks. Callers guard asynchronous results against connection identity and relevant selection/stream revisions.

The normalized values deliberately still use `OpenCodeProject`, `OpenCodeSession`, `OpenCodeMessageEnvelope`, `OpenCodeAgent`, and related model types. `BackendEvent.mutation` carries `OpenCodeTypedEvent`; `BackendMutationBridge` routes its supported subset into existing reducers. Typed action signals and session-form events share the same backend stream. This is a usable contract, not a new domain model independent of OpenCode semantics.

`BackendAdmission` distinguishes accepted, rejected, and uncertain input. Acceptance is not completed execution. Preserve caller-generated message identity and retained uncertain payload separately from canonical transcript state; do not automatically retry with a fresh ID. Tests cover stale callbacks, newer drafts, canonical evidence, and metering ownership.

## General Recovery Boundary

Recovery applies to **both Legacy and v2**; the user's actual issue was Legacy. Before scripted fixture acceptance, the real adapter regression reproduced `POST /session/.../prompt_async` returning 408, newer canonical live messages, then a GET missing the original input. The old merge left the original unknown input as a normal tail message. Retained payload now stays separate from canonical messages; queued/uncertain cards perform status GETs only, never automatic POSTs.

Same-owner raw-server/resolved-profile reconnect retains unknown text, files, mentions and original message ID in process memory, with session/scope ownership and foreign-scope isolation. **This recovery does not survive actual app kill and adds no database.** Existing disk transcript caching and persisted shortcut/action checkpoints do not imply recovery-payload persistence.

Exact canonical evidence overrides old local-prefix assumptions; optimistic rows, disk cache and widget admission ledgers cannot falsely confirm a submission. Canonical evidence is preserved independently of local ledger changes. Source/unit tests exercise the real adapter with mocked 408 responses, and seeded root/dedicated-window UI verifies both profiles. No personal-server restart or physical-phone symptom-resolution evidence is claimed. This remains OpenClient-owned recovery, not a generic persistent delivery guarantee for every harness.

Core acceptance also found two production bugs: New Session awaited execution and hid streaming behind its sheet, fixed by returning after admission with a guarded completion-reconciliation task; unfinished empty HTTP bodies erased live deltas, fixed only for matching unfinished live-owned parts. Completed canonical parts win, including completed parts inside ongoing messages. Neither fix turns local optimistic state into canonical evidence.

## Verified Root Wiring

`OpenCodeIOSClient/Facades/OpenClientComposition.swift` accepts `backendFactory: (any BackendFactory)?` and forwards it to `AppViewModel(backendFactory:)`. Supplying both a view model and a factory violates its precondition.

Current `OpenCodeIOSClientApp` and `OpenCodeMacApp` roots use `OpenClientComposition()`; the screenshot path instead injects a seeded view model. The roots pass composition facades into `RootView` and `ChatView`. No alternate product root or target is implemented here.

Schematic example only; `OtherHarnessFactory` is a placeholder, not an existing implementation:

```swift
// Future target's composition root, on the main actor:
let composition = OpenClientComposition(backendFactory: OtherHarnessFactory())

// The factory conforms to BackendFactory and implements:
// func connect() async throws -> BackendConnection
// Return a fresh BackendConnection with:
// projects: any BackendProjectsService
// sessions: any BackendSessionsService
// chat:     any BackendChatService
// models:   any BackendModelsService
// events:   any BackendEventSource
// Supply commands/projectLifecycle/worktrees/worktreeReset/sessionForms/sessionSelection
// only when the factory implements their concrete contracts.
// Then use the existing root/facade wiring and connection action.
```

`AppViewModel+Connection.swift` uses the injected factory, or defaults to `OpenCodeBackendFactory(client:eventManager:)`. The default factory negotiates Legacy/v2 and installs `OpenCodeBackendAdapter` for the four core services. The injected path skips saved OpenCode configuration/Keychain hydration, OpenCode auto-connect, and legacy persistent caching; composition does not start the OpenCode device bridge for an injected factory. It does not silently send another harness's intent to a saved OpenCode server.

The production factory also installs typed command and project-lifecycle services, v2 session forms and session selection, copy management for legacy or the exact `0.0.0-next-17155` runtime, and legacy-only reset. These are actual factory services, not just test doubles. Next-17155 uses `/api/project/:id/directories` and `/experimental/project/:id/copy` (plus `/copy/refresh`), not the pinned/newer `/api/worktree` contract. V2 creation requires an explicit absolute destination parent and does not fabricate v1 named-branch/startup readiness. Project resolution retains selected-clone and canonical-path identity on reconnect; workspace session pagination uses core services and Files enables workspace selection.

## What Is Still OpenCode-Specific

The optional typed services above are injectable. Remaining OpenCode-only features use `BackendConnection.openCodeCompatibility` to resolve `OpenCodeBackendAdapter`; `requireOpenCodeClient(for:)` requires both the advertised capability and that adapter. `AppViewModel.compatibilityClient(for:)` and facade/action guards protect these remaining calls.

Fork/compaction, files, terminal, MCP, provider configuration, legacy permissions/questions, bridge, and other unextracted surfaces still rely on compatibility paths. Advertising `.terminal` or `.commands` on another harness does not supply a transport implementation. Commands/actions, session forms and session selection use concrete services. Pass 8 wires games and widget mutations through typed core/optional services, but this does not make saved-server routes, commerce, extensions or every window surface harness-neutral. Window MCP explicitly retains `requireOpenCodeClient(for: .mcp)` compatibility. Keep unsupported features gated rather than adding a giant catch-all protocol.

V2 events are also not fully harness-neutral. `OpenCodeBackendEventSource.v2Event` delivers managed events to `AppViewModel.handleV2Event`, retaining specialized transcript projection, prompt admission, configuration invalidation, and revision-guarded canonical reconciliation. Status/diagnostics use the shared backend stream; v2 domain events are not falsely emitted as canonical legacy mutations. The legacy compatibility sink likewise preserves OpenCode metadata.

Core Activity, Home search, quick new chat, and previews use injected/core paths where appropriate. Project-action editor/chips and `ProjectActionCoordinator` now use typed commands and core session/chat services. Both profiles retain server sessions and hide only owned runs using `ProjectActionStore`'s scoped journal; `recoverActionRunHistory` reveals history. There is no delete fallback or server-archive claim, and HTTP/idle alone cannot indicate success. The paid command-plus-evaluation flow is mock-verified only; actual paused command admission is live-tested.

Native session, global and provider forms share `BackendFormContract` with a narrower provider policy. Session/global forms support optional/default/conditional fields, custom multiselect and explicit external acknowledgement; pattern/format validation remains server-authoritative. Unknown schemas/outcomes are not flattened or blindly retried. Pass 6 closes global MCP elicitation/project presentation through the optional service below. The shared foreground coalescer uses activation invalidation and per-session latest-request guards; it does not replace SSE or introduce mutation retries.

V2 project appearance remains read-only because next-17155 has no verified metadata writer. Destructive reset/archive and v1 named-branch/setup semantics lack a verified supported server contract, not implied by lifecycle/copy services. Pass 8 implements typed widget mutations, games, v2 Live Activities and dedicated-window presentation state; their verification and product-specific limits are below. OUR v2 plugin/native bridge/browser automation are explicitly user-deferred until OpenCode v2 release/contracts settle, not current blockers. Manual browsing is independent. Incomplete generic extraction is not automatically a missing v2 feature. Do not expand Git/repository-initialization parity without v1 feature proof. See [the adoption guide](OPENCODE_V2_ADOPTION_PLAN.md) and [parity checklist](V2_PARITY_CHECKLIST.md).

## Pass 8 Boundaries

- **Live Activities:** `OpenCodeChatActivityAttributes` and `LiveActivityFacade` own resolved profile/server/session identity plus exact OS activity identity. Persisted missing profile is legacy; unknown values fail closed. Attributes preserve project ID, canonical directory and workspace; separate `requestDirectory` keeps legacy Global requests unscoped without changing canonical identity. `OpenCodeLiveActivityActionClient` implements v2 permission transport. Typed forms use Open App, not inline legacy `[[String]]` answers. This remains an OpenClient/ActivityKit integration, not a generic backend extension SDK.
- **Restoration/lifecycle:** Cold-tap routing matches the exact OS record, connects to or joins its saved server/resolved profile, loads canonical session and pending permissions, then revalidates ownership after awaits. Same-owner reconnect reconciles retained activities rather than stopping all. `LiveActivityBackgroundBridge` uses a finite background assertion; no APNs or indefinite background execution. Native ActivityKit start/retain/reconnect/stop UI passed both simulators; cold-process OS restoration, Lock Screen and Dynamic Island remain unverified.
- **Widget actions:** New-session/command routes use typed backend services and canonical target/catalog validation, never fallback routes or fabricated commands. Create-once checkpoints retain exact admission identity; canonical acceptance wins over late rejection even after ledger pruning. One-shot reservations capture the commerce owner/day and never refund accepted input. Same-owner settled completion retires the handoff on reconnect; all route errors are owned. Product-specific saved-server/App Group/commerce coupling remains. Actual UI proves new-draft cancel and missing-command handling, not valid-command execution.
- **Games:** `FunAndGamesCoordinator`/`FunAndGamesStore` use core default-directory resolution, session creation/selection and hidden stable-identity setup for Find the Bug (12 languages) and Find the Place. Uncertain admission reconciles canonical reads, not reposts. Profile-scoped per-session rejected setup persists so an old session cannot become an unmetered ordinary send. Mock game flow is verified; UI chooser/cancel evidence is not actual provider execution/gameplay.
- **Dedicated windows:** `ChatWindowContext` and a real window-bound `ChatFacade` isolate selection, drafts/attachments, focus/navigation/history, hydration, form editing, browser and errors. Scoped MCP/todo refresh and child contexts use their own window scope; canonical stores, connection, session model-configuration barrier and one event source are shared. MCP uses OpenCode compatibility, so this is not all-harness independence. Audio leases prevent inactive-window teardown from deactivating another's audio.
- **Window routing/evidence:** Routes carry explicit profile/canonical directory/workspace; absent profile remains legacy and unknown profiles fail closed. Native iPad two-view UI preserves root draft while child editing; iPhone hides the action. Primary app shells are not independent multiwindow copies. Physical audio/keyboard behavior and OS restoration are still unverified.
- **Deferred decision:** The user explicitly deferred OUR v2 `OpenClientPlugin`, native bridge and browser automation until OpenCode v2 is released and contracts settle. Do not implement that port now or prioritize it as a current blocker. V2 server plugins exist; the legacy function is incompatible with object `setup`/effect APIs. This is a future port, not server plugin incapability.

## Selling A Separate App

A separate target can reuse the core UI/facades and choose its factory at composition. That is a practical next product boundary, **not** something this pass has built or validated. An API swap alone does not configure a separately sold app, isolate every product preference, or authorize sharing secrets across targets.

| Future target decision | Current coupling to address explicitly |
| --- | --- |
| Factory and connection UX | Choose the harness factory, authentication/configuration ownership, and exposed features. Existing connection UI remains OpenCode-oriented. |
| Brand | App/display name, icons, copy, screenshots, onboarding, and store listing. |
| Bundle IDs and URL scheme | Unique app/extension identifiers, provisioning, scheme and deep-link parsing. `project.yml` validates existing OpenClient IDs; changing only an API URL is insufficient. |
| Keychain | Choose distinct access groups and service/account namespaces. `OpenCodeServerPasswordStore` and commerce usage storage currently use OpenClient service names. |
| App Group and local data | Choose distinct entitlements/container IDs for defaults, caches, widget snapshots, and share payloads. Shared helpers currently name `group.com.ntoporcov.openclient`. |
| Commerce | Choose the new product's StoreKit IDs, entitlement/paywall/metering policy, persistence, and validation configuration. Backend injection does not replace `CommerceFacade` or its existing OpenClient product IDs. |
| Support and module identity | Choose support/privacy/marketing/update destinations; verify product/module names, test imports, resources, and extension principal-class references. Shared source is not yet a separately packaged public SDK. |

**Default to separate secrets and data for separately sold products.** A different bundle ID is not sufficient if existing shared Keychain/App Group entitlements and hard-coded namespaces are copied. Conversely, sharing source or swapping APIs cannot grant cross-target Keychain access. Any deliberate sharing needs matching authorized entitlements plus an explicit scope/migration decision; never use backend descriptor IDs as secrets or as a substitute for OS isolation. Sharing within one product's app/extensions is a separate decision from sharing between products.

No generic branding/identity configuration API is claimed to exist. The table identifies concrete target-composition work, not parameters already accepted by `OpenClientComposition`.
